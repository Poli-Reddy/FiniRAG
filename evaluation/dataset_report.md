# FiniRAG — Dataset Evaluation Report

Generated by `evaluation/build_report.py` from the raw pipeline
responses in `evaluation/results/`. Every row is a real run of
`DocumentService.process_document` — the same entry point the API uses.

Persistence is the one thing stubbed out: the evaluation writes no rows
to the database, so the dashboard keeps showing the user's own uploads.
Persistence is covered separately by 14 integration tests that write and
read real rows against the live PostgreSQL instance
(`pytest backend/tests/test_repository.py -m integration`).

## File-gate edge cases

The dataset contains only well-formed documents, so these four are
generated by the harness and pushed through the same entry point. Each
must fail *gracefully* with a specific error code, not raise.

| Input | Scenario | Detected type | Pages | Status | Error code |
|---|---|---|---|---|---|
| `edge_corrupted.pdf` | Valid PDF header, truncated body | application/pdf | 0 | FAILED | `CORRUPTED_FILE` |
| `edge_empty_file.pdf` | Zero-byte upload | — | 0 | FAILED | `EMPTY_FILE` |
| `edge_four_pages.pdf` | One page over the 3-page limit | application/pdf | 4 | FAILED | `PAGE_LIMIT_EXCEEDED` |
| `edge_unsupported_type.txt` | Plain text uploaded as an invoice | text/plain | 0 | FAILED | `UNSUPPORTED_FILE_TYPE` |

## How to reproduce

```bash
./venv/Scripts/python.exe evaluation/run_evaluation.py   # ~30 min, calls Gemini
./venv/Scripts/python.exe evaluation/build_report.py     # instant, reads results/
./venv/Scripts/python.exe evaluation/tolerance_sensitivity.py
```

`run_evaluation.py` is resumable: a document that already has a result
file is skipped, so an interrupted run costs nothing to restart.
